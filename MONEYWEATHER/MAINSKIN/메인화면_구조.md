# 메인화면 구조

`시안/블로그 메인 스킨 전체.png` 를 위에서부터 뜯어본 것이다.
`skin.html`을 쓸 때 이 문서대로 짠다.

---

## 1. 전체 구성

```text
헤더          로고 (왼쪽)                        검색 (오른쪽)
───────────────────────────────────────────────
히어로        「내 재테크 온도는 몇 도일까?」
              한 줄 설명 + 「최신 글 보기」 버튼
              오른쪽에 온도계 일러스트
───────────────────────────────────────────────
카테고리      「최신 재테크 글」                   더보기 >
              [카드][카드][카드][카드][카드]
───────────────────────────────────────────────
꼬리말        로고    소개·문의·개인정보처리방침    저작권
```

**사이드바가 있다.** 실제 블로그를 확인한 결과 오른쪽 사이드바를 유지하기로 했다 (2026-09-09).
시안에는 사이드바가 없어서 이 부분은 시안과 다르게 간다. §9를 본다.

## 2. 카드 하나의 구조

카드 다섯 장은 **카테고리 다섯 개**다. 각 카드 아래에 그 카테고리의 최신 글이 붙는다.

```text
┌────────────────────┐
│                    │
│   카테고리 그림      │  ← thumb-*.png (16:9)
│                    │
├────────────────────┤
│ 투자                │  ← 카테고리 이름 (카드 전체가 카테고리 링크)
│                    │
│ · 배당률 10% ETF…   │  ← 이 카테고리의 최신 글
│ · PER이 낮으면…     │
│ · 국내상장 해외…    │
└────────────────────┘
```

카테고리 이름과 그림 파일은 `00_브랜드/카테고리.md` 에 정의돼 있다.

---

## 3. 문제 — 티스토리는 이걸 그냥은 못 한다

**「특정 카테고리의 최신 글」을 뽑는 치환자가 없다.**

공식 스킨 문서를 확인한 결과다.

| 확인한 것 | 결과 |
| --- | --- |
| 사이드바 요소 | 최근 공지 · 최근 글 · 인기글 · 최근 댓글 · 카테고리 · 랜덤태그 · 방문자수 · 검색 |
| 「최근 글」에 카테고리 한정 옵션 | 문서에 없음. 블로그 **전체** 최신 글이다 |
| 목록 치환자 | 지금 보고 있는 목록 하나만 그린다. 한 화면에 5개를 못 그린다 |

즉 치환자만으로는 **카드 아래를 채울 수 없다.** 방식을 골라야 한다.

---

## 4. 방법 세 가지

### A안 — 자바스크립트가 카테고리 페이지를 읽어온다 (권장)

```text
메인이 열린다
    ↓
카드 5장이 먼저 그려진다 (그림 + 카테고리 이름)
    ↓
자바스크립트가 카테고리 주소 5개를 동시에 불러온다
    /category/재테크 기초
    /category/투자
    /category/세금
    /category/부동산
    /category/오늘의 머니온도
    ↓
받아온 화면에서 글 제목과 주소를 뽑아낸다
    ↓
카드 아래에 끼워 넣는다
```

**장점**

- 글을 새로 쓰면 알아서 반영된다. 손댈 게 없다
- 글이 아무리 쌓여도 각 카테고리의 진짜 최신 글이 나온다
- 같은 블로그 주소라 외부 요청이 아니다. 차단당할 일이 없다
- 읽어오는 화면의 생김새를 **우리가 정한다.** 우리 스킨이니까 구조가 안 바뀐다

**단점과 대비**

| 단점 | 어떻게 |
| --- | --- |
| 첫 화면에 글 목록이 잠깐 늦게 뜬다 | 그림과 카테고리 이름은 먼저 뜬다. 빈 화면은 안 보인다 |
| 자바스크립트가 막히면 목록이 안 나온다 | **카드 전체를 링크로 만든다.** 목록이 없어도 눌러서 들어갈 수 있다 |
| 검색엔진이 이 목록을 못 볼 수 있다 | 글은 카테고리 페이지와 사이트맵으로 색인된다. 메인의 이 목록이 색인될 필요가 없다 |

### B안 — 홈의 전체 최신 글을 다섯 칸으로 나눈다

홈 목록에 나오는 글들을 화면에 숨겨두고, 자바스크립트가 카테고리별로 갈라 카드에 넣는다.

**장점** — 추가 요청이 없다. 화면이 뜨는 순간 바로 채워진다.

**단점** — 홈 한 페이지에 나오는 글 수 안에서만 나눌 수 있다.
글이 쌓여서 「부동산」 최신 글이 최근 20개 밖으로 밀려나면 **그 칸이 빈다.**

글이 아직 적을 때는 B안이 더 빠르고 간단하다. 쌓이면 무조건 A안이어야 한다.

### C안 — 카드 아래를 최신 글 말고 다른 걸로

카테고리 설명 한 줄과 글 개수만 넣는다. 치환자만으로 되고 실패할 일이 없다.
대신 메인에서 글 제목이 안 보여서, 독자가 한 번 더 눌러야 글을 만난다.

---

## 5. 결정 — A안

**A안으로 간다. 정해졌다.**

B안은 지금은 편하지만 글이 쌓이면 반드시 고쳐야 한다.
어차피 고칠 거면 처음부터 A안으로 짜는 게 낫다. 작업량 차이도 크지 않다.

A안이 실패했을 때 카드가 그냥 **카테고리 바로가기**로 남도록 만든다.
그러면 어떤 경우에도 화면이 깨지지 않는다.

## 7. 확인이 필요한 것

- **카테고리 주소 형태** — 티스토리에 카테고리를 만든 뒤 실제 주소를 확인한다.
  이름에 공백이 있어서(`재테크 기초`) 주소에서 어떻게 바뀌는지 봐야 한다
- **홈 화면 설정** — 티스토리 홈을 「커버」로 두면 우리가 짠 히어로와 충돌할 수 있다.
  스킨을 올리기 전에 홈 화면 설정을 확인한다

## 8. 광고 자리 (애드센스 승인 후)

**애드센스 자동 광고의 「사이드 레일」에 맡긴다. 스킨에 광고 칼럼을 만들지 않는다.**

사이드 레일은 데스크톱에서 화면 옆에 고정되는 광고다.
구글이 남는 공간을 보고 알아서 띄운다. 우리가 자리를 만들 필요가 없다.

오른쪽에 띄우고 싶다는 것은 **애드센스 설정**에서 지정한다. 스킨과 무관하다.

### 스킨이 해야 할 일

우리가 자리를 안 만드는 대신, **광고가 들어올 공간을 남겨둬야 한다.**

| | |
| --- | --- |
| **본문 최대 폭 1200px 유지** | 화면 양옆에 빈 공간이 남는다. 여기에 레일이 들어간다 |
| **본문을 화면 전체 폭으로 늘리지 않는다** | 늘리면 레일이 들어올 자리가 없어서 안 나온다 |
| **화면 가장자리에 우리 요소를 고정하지 않는다** | 「맨 위로」 버튼 같은 것. 레일과 겹친다 |
| **애드센스 스크립트를 `<head>`에 넣는다** | 자동 광고는 이것만 있으면 된다 |

### 화면이 좁으면 안 나올 수 있다

레일이 뜨려면 옆에 폭이 필요하다. 본문이 1200px일 때 남는 공간은 이렇다.

| 화면 폭 | 한쪽에 남는 공간 | |
| --- | --- | --- |
| 1920px | 360px | 넉넉하다 |
| 1536px | 168px | 나온다 |
| 1440px | 120px | 아슬아슬하다 |
| 1366px | 83px | 안 나올 가능성이 높다 |

**일단 1200px로 간다.** 승인 후 실제로 레일이 안 뜨면 그때 본문을 1120px로 줄인다.
줄이면 좁은 화면에서도 뜨지만 카드가 224px에서 208px로 작아진다.
미리 줄여놓고 손해 보지 말고, 확인하고 나서 정한다.

### 알아둘 것

- **사이드 레일은 앵커 광고와 묶여 있다.** 앵커 광고를 켜면 레일이 따라온다.
  앵커 광고는 휴대폰 화면 아래에 붙는 광고다. 이게 싫으면 설정에서 따로 확인한다
- **자동 광고는 본문 안에도 광고를 넣는다.** 글 중간에 끼어들어 흐름을 끊을 수 있다.
  자동 광고 설정에서 형식별로 켜고 끌 수 있으니 승인 후 보면서 조절한다
- **승인 전에는 아무것도 안 보인다.** 지금 단계에서 스킨에 넣을 것이 없다

### 하지 말 것

`CLAUDE.md` §66은 「콘텐츠보다 광고가 앞서는 구조」를 발행 중단 조건으로 둔다.

- 사이드 레일과 별도로 우리가 만든 광고 칼럼을 또 두지 않는다. 겹쳐서 광고가 과해진다
- 첫 화면에서 광고가 히어로보다 먼저 눈에 들어오게 하지 않는다

## 9. 헤더와 사이드바 (2026-09-09 결정)

### 헤더는 A안 — 로고와 검색만

```text
[로고]                                          🔍
```

햄버거 메뉴를 쓰지 않는다. 로고를 누르면 홈으로 간다.

**카테고리 이동은 사이드바가 담당한다.** 그래서 헤더에 카테고리를 펼치지 않아도 된다.
앞서 걱정했던 「글 읽다가 다른 카테고리로 가는 길이 없다」는 문제가 사이드바로 해결된다.

### 사이드바를 유지한다

실제 블로그의 사이드바에는 이런 것들이 들어 있다.

```text
분류 전체보기
  재테크 기초 / 투자 / 세금 / 부동산 / 오늘의 돈 이야기 / 한눈에 보기
공지사항
최근글 · 인기글
최근댓글
태그
```

### 문제 — 사이드바가 있으면 카드 5열이 안 들어간다

| | 폭 |
| --- | --- |
| 전체 | 1200px |
| 사이드바 | 260~300px |
| 사이 간격 | 40px |
| **남는 본문** | **860~900px** |

카드 5장을 860px에 넣으면 한 장이 **159px**이다. 썸네일이 우표만 해진다.
시안의 5열이 성립하지 않는다.

### 해결 — 홈만 전체 폭으로 쓴다

```text
홈          사이드바 없음, 본문 1200px      → 히어로 + 카드 5열 (시안 그대로)
목록·글     사이드바 있음, 본문 860~900px   → 사이드바로 카테고리 이동
```

홈은 카드 5장이 이미 카테고리 역할을 해서 사이드바가 없어도 된다.
사이드바가 정말 필요한 곳은 **글을 읽는 중**이고, 거기서는 카드가 없다.

구현은 자바스크립트 한 줄로 한다. 홈이면 `<body>`에 표시를 달고,
그 표시가 있을 때만 CSS가 사이드바를 숨기고 본문을 넓힌다.

```text
홈인가?  →  body에 표시 추가  →  CSS가 사이드바 숨김 + 본문 1200px
아니면   →  그대로            →  사이드바 보이고 본문 860px
```

### 광고 사이드 레일에 미치는 영향

§8에서 본문 1200px 양옆의 빈 공간에 사이드 레일이 들어간다고 했다.
사이드바가 생겨도 **전체 폭은 여전히 1200px**이라 그 계산은 그대로다.
홈에서만 본문이 1200px를 다 쓰고, 나머지 페이지는 1200px 안에서 나눠 쓴다.
