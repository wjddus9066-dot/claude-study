# 2. Single Source of Truth

한 규칙을 여러 문서에서 다시 정의하지 않는다.

### 기준 문서

- **현재 콘텐츠 상태** → `콘텐츠지도.md`
- **LEVEL·선행 개념** → `CONTENT_ARCHITECT.md`
- **카테고리** → `카테고리.md`
- **문체** → `글쓰기톤.md`
- **색상** → `색상.md` + `팔레트.js`
- **조사·사실·출처·계산·썸네일·내부링크·정책 등 세부 운영** → `CLAUDE.md`
- **최종 PASS/FIX** → `CONTENT_CHECKLIST.md`
- **검색 구조** → `SEARCH_MAP.md`
- **현재 이슈 탐지** → `TREND_RADAR.md`

다른 문서는 해당 규칙을 복사하지 않고 **참조한다.**

# 4. 각 시스템의 관계

## TREND RADAR

**“지금 무엇이 바뀌었고, 사람들이 무엇을 궁금해하는가?”**를 찾는다.

새로운 `LEVEL 2 — CURRENT ISSUE` 후보를 발견하는 역할이다.

---

## CONTENT_ARCHITECT

**“이 질문을 어떻게 이해시키는가?”**를 설계한다.

```text
LEVEL 1 — FOUNDATION
“이게 뭔데?”
        ↓
LEVEL 2 — CURRENT ISSUE
“지금 무슨 일이야?”
        ↓
LEVEL 3 — PRACTICAL
“그래서 뭘 해?”
```

선행 개념을 전부 독립 글로 만들지 않는다.
반복적으로 필요하거나 독립적인 검색 의도가 있는 개념만 FOUNDATION으로 뗀다.

---

## 콘텐츠지도

**“우리 블로그에 실제로 무엇이 있고 무엇이 비어 있는가?”**를 관리한다.

발행 상태, 우선순위, 내부 링크 가능 글, 콘텐츠 공백을 관리한다.

---

## SEARCH_MAP

**“사람은 어떻게 찾고, 검색 시스템과 AI는 어떻게 이해하는가?”**를 설계한다.

```text
SEO = 발견
AEO = 답변
GEO = 명확한 사실과 문맥 이해
```

---

# 5. SEO·AEO·GEO는 브랜드를 대신하지 않는다

검색 최적화는 블로그의 목적이 아니다.

먼저 사람에게 필요한 설명을 만든다.
그다음 검색과 AI가 그 설명을 잘 발견하고 이해하도록 구조화한다.

```text
독자의 실제 질문
↓
쉬운 설명
↓
정확한 사실
↓
실제 돈의 의미
↓
오늘 확인할 것
↓
SEO / AEO / GEO 구조화
```

---

# 6. 기존 운영 규칙과의 관계

`CLAUDE.md`에는 이미 GEO와 겹치는 규칙이 많이 존재한다.
따라서 SEARCH_MAP에서는 이를 복사하지 않는다.

예:

- 인라인 출처 → `CLAUDE.md`
- 기준일 → `CLAUDE.md`
- 원자료 우선 → `CLAUDE.md`
- 사실관계 검증 → `CLAUDE.md`
- 계산 표시 → `CLAUDE.md`
- 썸네일 → `CLAUDE.md`
- 내부 링크 → `CLAUDE.md`

SEARCH_MAP은 **검색 설계 단계에서 무엇을 확인할지**만 정하고, 실제 운영 방식은 `CLAUDE.md`를 따른다.

# 7. 최종 원칙

```text
TREND를 발견한다.
↓
독자가 궁금해하는 질문을 찾는다.
↓
현재 콘텐츠 구조를 확인한다.
↓
필요한 만큼만 기초를 설명한다.
↓
현재 이슈를 쉽게 설명한다.
↓
숫자와 제도를 실제 돈으로 번역한다.
↓
독자가 오늘 확인할 것을 알려준다.
↓
관련 글과 다음 질문으로 연결한다.
```

> **MONEYWEATHER는 경제 전문가처럼 보이기 위해 어려운 내용을 늘리는 블로그가 아니다.**
>
> **어려운 경제를 독자와 같이 공부하면서, “그래서 내 돈은?”까지 번역해주는 블로그다.**
