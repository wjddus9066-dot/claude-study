# CONTENT_ARCHITECT

## 1. 역할

새로운 콘텐츠를 작성하기 전에 **독자가 이 주제를 이해하기 위해 필요한 개념과 연결해야 할 콘텐츠를 설계한다.**

목표는 글 하나를 만드는 것이 아니라,

> **하나의 글이 블로그 전체 지식 구조와 연결되도록 만드는 것**

이다.

현재 콘텐츠 상태와 발행 여부는 `03_콘텐츠/콘텐츠지도.md`에서 확인한다.

검색 의도·SEO·AEO·GEO는 `00_브랜드/SEARCH_MAP.md`에서 정한다.

---

# 2. 콘텐츠 3단계 구조

## LEVEL 1 — FOUNDATION

초보자가 알아야 하는 기초 개념.

예:

- 기준금리란?
- COFIX란?
- 금융채란?
- 대출금리는 어떻게 결정될까?
- 고정금리와 변동금리 차이

### 원칙

검색량만 보고 무작정 만든다.

→ **현재 이슈에서 반복적으로 필요해진 개념을 우선한다.**

---

## LEVEL 2 — CURRENT ISSUE

현재 사람들이 궁금해하는 경제·금융 이슈.

예:

- 기준금리 3%인데 내 대출이자는 왜 그대로일까?
- 예금금리는 내려가는데 대출금리는 왜 그대로일까?

이 단계는 독자의 **“지금 궁금한 것”**을 해결한다.

새로운 CURRENT ISSUE는 `03_콘텐츠/TREND_RADAR.md`가 발견할 수 있다.

---

## LEVEL 3 — PRACTICAL

독자가 실제로 행동하거나 판단해야 하는 문제.

예:

- 지금 고정금리로 갈아타야 할까?
- 대출 갈아타기 전에 무엇을 확인해야 할까?

---

# 3. 새로운 주제 분석 절차

### STEP 1
독자가 실제로 궁금한 질문은 무엇인가?

### STEP 2
현재 독자가 원하는 답을 한두 문장으로 말할 수 있는가?

### STEP 3
그 답을 이해하기 위해 필요한 선행 개념은 무엇인가?

### STEP 4
선행 개념 중 반드시 별도 설명이 필요한 것은 무엇인가?

### STEP 5
`콘텐츠지도.md`에 이미 해당 글이 있는가?

### STEP 6
있다면 발행된 글을 내부 링크한다.

### STEP 7
없다면 현재 글에서 짧게 설명하고, 필요할 경우 FOUNDATION 후보로 기록한다.

### STEP 8
이 글을 읽은 뒤 독자가 실제로 다음에 판단하거나 행동할 문제는 무엇인가?

→ PRACTICAL 후보를 만든다.

---

# 4. 선행 개념 처리 규칙

## 별도 기초 글이 필요한 경우

- 독자가 이해하기 어려운 핵심 개념
- 여러 글에서 반복적으로 등장하는 개념
- 하나의 개념만으로도 독립적인 검색 의도가 있는 경우
- 이후 여러 콘텐츠의 기반이 되는 경우

## 현재 글에서 짧게 설명할 경우

- 간단한 용어
- 현재 주제를 이해하는 데만 필요한 개념
- 별도 콘텐츠로 만들 가치가 낮은 개념

---

# 5. 콘텐츠 연결 구조

가능하면:

```text
FOUNDATION
    ↓
CURRENT ISSUE
    ↓
PRACTICAL
```

예:

```text
기준금리란?
    ↓
기준금리 3%인데 내 대출금리는 왜 그대로일까?
    ↓
대출 갈아타기 해야 할까?
```

한 글에서 모든 것을 설명하려 하지 않는다.
독자가 다음 단계에서 필요한 글로 자연스럽게 이동할 수 있게 한다.

---

# 6. 독자 경험 설계

새로운 글은 반드시 다음 질문을 통과한다.

1. 독자는 왜 이 글을 클릭하는가?
2. 첫 부분에서 원하는 답을 얻는가?
3. 설명이 어려워서 이탈할 부분은 어디인가?
4. 비유가 필요한 부분은 어디인가?
5. 표·차트가 글보다 이해하기 쉬운 부분은 어디인가?
6. 숫자를 생활비·금액으로 번역해야 하는 부분은 어디인가?
7. 이 글을 읽고 독자가 무엇을 할 수 있는가?
8. 다음에 읽을 콘텐츠는 무엇인가?

실제 말투와 글의 고정 앞뒤 구조는 `글쓰기톤.md`가 유일한 기준이다.
시각자료 색상은 `색상.md`를 따른다.

---

# 7. 최종 설계 출력

글을 작성하기 전에 내부적으로 다음을 정리한다.

- LEVEL
- 핵심 질문
- 핵심 답변
- 필요한 선행 개념
- 내부 링크 후보
- 비유가 필요한 부분
- 시각화가 필요한 부분
- 숫자 번역이 필요한 부분
- 독자가 취할 행동
- 다음 콘텐츠 후보

SEO·AEO·GEO 정보는 `00_브랜드/SEARCH_MAP.md`에서 별도로 정리한다.

이 분석의 목적은 글을 어렵게 만드는 것이 아니라 **불필요한 설명을 제거하는 것**이다.

# 8. 독자 이해 엔진 (UNDERSTANDING ENGINE) (옛 CLAUDE.md §1)

이 장은 moneyweather의 정체성이자 가장 중요한 부분이다.

**모든 경제·금융 콘텐츠는 "독자 이해 엔진"을 통과해야 한다.**

---

## 8.1 핵심 데이터 처리 과정 (옛 §1.1)

모든 핵심 데이터는 다음 과정을 거친다.

```text
RAW DATA
↓
무슨 숫자인가?
↓
이전과 얼마나 달라졌는가?
↓
왜 변했는가?
↓
좋은 것인가 / 나쁜 것인가?
↓
그래서 경제에 어떤 의미인가?
↓
그래서 직장인에게 어떤 의미인가?
↓
가능하다면 내 돈으로 얼마인가?
↓
표/차트로 보여줄 필요가 있는가?
```

---

## 8.2 DATA_TRANSLATOR (옛 §1.2)

원자료의 숫자·지표·통계를 독자가 이해할 수 있는 의미로 변환한다.

### 목적

경제·금융 데이터와 숫자를 독자가 이해할 수 있는 의미로 변환한다.

### 반드시 확인할 것

* 이 숫자는 무엇을 의미하는가?
* 기준일은 언제인가?
* 이전 값과 비교하면 어떻게 변했는가?
* 변화폭은 얼마인가?
* 이 변화가 중요한 이유는 무엇인가?
* 일반인이 체감할 수 있는 숫자로 바꿀 수 있는가?
* 독자가 이 숫자를 보고 실제로 무엇을 이해해야 하는가?

### 원칙

숫자를 나열하지 않는다.

숫자의 의미를 함께 설명한다.

```text
RAW DATA
→ 변화
→ 의미
→ 영향
→ 생활 속 의미
```

---

## 8.3 EASY_EXPLAINER (옛 §1.3)

전문용어·경제 개념·정책 내용을 비전문가의 언어로 설명한다.

### 목적

전문가가 아닌 독자가 경제·금융 개념을 이해할 수 있도록 설명한다.

### 원칙

* 전문용어를 그대로 사용하지 않는다.
* 전문용어가 필요하면 최초 등장 시 반드시 풀어서 설명한다.
* 한 문장에 하나의 핵심만 담는다.
* 어려운 개념은 쉬운 말 → 필요한 경우 비유 → 실제 사례 순서로 설명한다.
* "그래서?"라는 질문에 답한다.
* "이게 내 생활이나 돈과 무슨 관계인가?"를 가능한 경우 설명한다.
* 지나치게 어린이처럼 설명하지 않는다.
* 쉬운 설명을 위해 정확성을 희생하지 않는다.
* 쉽게 쓴 문장은 마지막에 **CLAUDE.md §38.5 FACTUAL_ACCURACY_RULES**로 한 번 더 거른다. 「묶인다」「못 뺀다」처럼 짧게 끊은 문장일수록 조건이 잘렸는지 본다.

### 목표

전문가처럼 보이는 글이 아니라

**비전문가가 이해할 수 있는 글**을 만든다.

---

## 8.4 VISUAL_PLANNER (옛 §1.4)

독자의 이해를 높일 수 있는 표·차트·인포그래픽·비교자료를 설계한다.

### 목적

텍스트보다 표·차트·인포그래픽으로 보여주는 것이 이해에 도움이 되는 부분을 찾아낸다.

### 판단 대상

* 비교
* 추이
* 비율
* 금액 차이
* 기간 변화
* 구성 비중
* 순위
* 원인과 결과
* 정책 변화
* 전후 비교

### 원칙

시각자료를 장식으로 사용하지 않는다.

"예쁘게 보이는가?"보다

**"이 자료가 독자의 이해를 높이는가?"**를 우선한다.

필요하지 않은 표와 차트는 만들지 않는다.

---

## 8.5 세 역할의 연결 (옛 §1.5)

세 역할은 독립적으로 수행하지 않고 서로 결과를 전달한다.

```text
DATA_TRANSLATOR
        ↓
"이 숫자가 무슨 뜻이지?"
        ↓
EASY_EXPLAINER
        ↓
"이걸 어떻게 하면 쉽게 이해하지?"
        ↓
VISUAL_PLANNER
        ↓
"글보다 표·차트·그림으로 보여주는 게 낫지 않을까?"
```

---

## 8.6 가장 중요한 원칙 (옛 §1.6)

> **"표를 만들기 위해 데이터를 넣지 않는다."**

이해시키기 위해 필요한 데이터를 선택하고,

**그 데이터를 가장 쉽게 이해할 수 있는 형태로 보여준다.**

---

# 9. 콘텐츠의 핵심 질문과 품질 공식 (옛 CLAUDE.md §9)

모든 콘텐츠는 가능하면 다음 질문 중 하나 이상에 답해야 한다.

| 질문 | 내용 |
| --- | --- |
| WHAT | 무슨 일이 일어났나? |
| WHY | 왜 이런 일이 생겼나? |
| SO WHAT | 그래서 내 돈과 생활에 어떤 의미인가? |
| WHO | 누가 영향을 받는가? |
| WHEN | 언제부터 적용되는가? |
| HOW MUCH | 얼마나 영향을 받는가? |
| WHAT TO DO | 그래서 나는 무엇을 확인하거나 준비해야 하는가? |

콘텐츠 품질은 다음 요소의 결합으로 판단한다.

> **품질 = 정확성 × 독자 가치 × 독창성 × 최신성 × 가독성 × 검증 가능성**

어느 하나가 0이면 전체 품질이 크게 떨어진다.

# 10. 콘텐츠 유형별 전략 (옛 CLAUDE.md §11)

## TYPE A — 경제 이슈 설명형

```text
무슨 일이 일어났나
→ 왜 발생했나
→ 핵심 숫자
→ 시장에 미치는 영향
→ 직장인에게 어떤 의미인가
→ 앞으로 확인할 것
```

## TYPE B — 투자/ETF 분석형

```text
상품/기업 개요
→ 핵심 지표
→ 장점
→ 단점
→ 위험요인
→ 어떤 투자자에게 적합한가
→ 비교
→ 결론
```

## TYPE C — 세금/제도 설명형

```text
핵심 결론
→ 대상
→ 조건
→ 금액/세율
→ 적용 시점
→ 예외
→ 실제 사례
→ 주의사항
→ 공식 출처
```

## TYPE D — 부동산/청약형

```text
핵심 결론
→ 대상 주택/제도
→ 자격
→ 가격/대출
→ 세금
→ 장단점
→ 실제 시나리오
→ 주의사항
→ 공식 출처
```

## TYPE E — 생활재테크형

```text
문제 제시
→ 왜 손해인지
→ 숫자로 비교
→ 실제 사례
→ 해결 방법
→ 체크리스트
```

# 11. 경제지표 설명 공식 (옛 CLAUDE.md §15)

경제지표를 사용할 때는 다음 5단계를 기본으로 한다.

```text
① 이게 뭔데?
↓
② 숫자가 높으면 좋은 건가? 낮으면 좋은 건가?
↓
③ 왜 변했는데?
↓
④ 그래서 경제/시장에 어떤 영향을 주는데?
↓
⑤ 그래서 일반인은 무엇을 보면 되는데?
```

지표마다 의미가 다르므로 같은 방식으로 설명하지 않는다.

| 지표 | 쉽게 말하면 |
| --- | --- |
| 물가 | 생활비와 가격 상승 속도 |
| 금리 | 돈을 빌리는 비용 |
| 환율 | 외국 돈을 사기 위해 필요한 원화의 가격 |
| 실업률 | 일할 의사가 있는 사람 중 일자리를 구하지 못한 사람의 비율 |
| GDP | 일정 기간 동안 한 나라에서 만들어진 재화와 서비스의 전체 규모 |
| PER | 기업이 벌어들이는 이익에 비해 주가가 어느 정도 가격을 받고 있는지 |
| PBR | 기업이 가진 순자산에 비해 주가가 몇 배 수준인지 |

단순 정의만 하지 않는다.

**"이 숫자가 변하면 무엇이 달라지는가?"**를 함께 설명한다.

---

# 12. 투자지표 설명 원칙 (옛 CLAUDE.md §16)

PER, PBR, ROE, EPS, FCF, EBITDA 등 투자지표를 사용할 경우 전문가용 설명을 그대로 쓰지 않는다.

다음 구조를 기본으로 한다.

```text
지표 이름
↓
한 줄 정의
↓
쉽게 말하면
↓
숫자가 높으면?
↓
숫자가 낮으면?
↓
무조건 좋은가?
↓
어떤 지표와 함께 봐야 하나?
↓
실제 기업 사례
```

## "높으면 무조건 좋다" 금지

지표는 단독으로 평가하지 않는다.

> PER이 낮으니 저평가다.

라고 단정하지 않는다. 대신

> PER이 낮다는 것은 현재 이익에 비해 주가가 상대적으로 낮게 평가되고 있을 가능성을 보여줍니다.
>
> 하지만 성장률이나 업종 특성, 일시적인 이익 증가 여부에 따라 해석이 달라질 수 있습니다.

처럼 설명한다.

---

# 13. 숫자를 생활 단위로 바꾸는 규칙 (옛 CLAUDE.md §17)

## 변화량을 함께 보여준다

가능하면 `100 → 110`보다 **10% 증가**를 함께 보여준다.

## 퍼센트와 퍼센트포인트

독자가 헷갈리기 쉬운 개념은 반드시 설명한다.

> 금리가 3%에서 2.5%로 내려갔다면 **0.5%포인트 하락**입니다.
>
> 단순히 "0.5% 하락"이라고 쓰면 다른 의미가 될 수 있기 때문에 구분해야 합니다.

## 생활 예시로 변환

가능하면 다음 단위를 활용한다.

월 / 연 / 1억원 / 1,000만원 / 월급 / 월 이자 / 연 이자 / 실제 구매가격 / 실제 세금 / 실제 배당금

> 연 6% 수익률

보다

> 1,000만원을 투자했을 때 단순 계산으로 연 60만원 수준입니다.

처럼 이해 가능한 숫자로 바꾼다.

단, **세금·수수료·복리 등을 반영하지 않은 단순 계산이라면 반드시 명시한다.**

## 계산 과정을 숨기지 않는다

가능한 경우 단순 계산을 직접 수행하여 독자가 이해하기 쉬운 숫자로 변환한다.

```text
원자료:
금리 0.5%p 하락

↓

가정:
대출 3억원

↓

계산:
300,000,000 × 0.005

↓

연간 단순 이자 차이:
1,500,000원

↓

독자용 설명:
"단순 계산으로 연간 약 150만원의 이자 차이가 날 수 있습니다."
```

계산 과정과 가정을 숨기지 않는다.

## 숫자가 자료마다 다를 때

숫자가 서로 다른 자료에서 다르면 이유를 확인한다.

* 기준일 차이
* 장중/종가 차이
* 세전/세후 차이
* 환율 적용 차이
* 집계방식 차이
* 발표 시점 차이

확인하지 못하면 임의로 하나를 선택하지 않는다.

또한 다음 구분을 혼동하지 않는다.

* 세전 / 세후
* 명목 / 실질
* 월 / 분기 / 연간 기준
* 전년 대비 / 전월 대비

# 14. 데이터 선택과 번역 (옛 CLAUDE.md §18)

## 데이터가 많다고 좋은 글이 아니다

독자가 이해할 수 있는 데이터만 선택한다.

```text
이 숫자가 독자의 이해를 돕는가?
        ↓
YES → 사용
NO → 삭제
```

## 데이터 우선순위

| 순위 | 내용 |
| --- | --- |
| 1순위 | 독자의 판단에 직접 필요한 숫자 |
| 2순위 | 변화를 보여주는 숫자 |
| 3순위 | 비교에 필요한 숫자 |
| 4순위 | 배경 설명에 필요한 숫자 |
| 5순위 | 흥미롭지만 없어도 되는 숫자 |

5순위 데이터는 과감하게 삭제한다.

## 데이터 3단계

모든 핵심 데이터에는 가능하면 설명을 붙인다.

```text
DATA → MEANING → IMPACT
```

* **DATA** — 무슨 숫자인가?
* **MEANING** — 그 숫자가 어떤 상태를 의미하는가?
* **IMPACT** — 그래서 사람과 시장에는 어떤 영향을 줄 수 있는가?

### 숫자만 제시

> 기준금리 2.50%

### moneyweather

> 기준금리는 현재 2.50%입니다.
>
> 쉽게 말하면 한국은행이 정하는 **"돈의 기본 가격"** 같은 역할을 합니다.
>
> 이 금리가 움직이면 대출금리와 예금금리, 투자시장에도 영향을 줄 수 있습니다.

## 숫자 나열 금지

다음과 같은 문단을 피한다.

> GDP 2.1%, CPI 2.4%, 기준금리 2.5%, 실업률 3.1%를 기록했습니다.

독자는 그래서 무엇을 알아야 하는지 모른다. 대신

> 최근 경제지표를 한꺼번에 보면 숫자가 많아 보이지만 핵심은 두 가지입니다.
>
> **물가 상승 속도는 둔화되고 있고, 고용시장은 아직 크게 무너지지 않은 상황입니다.**
>
> 각각의 숫자를 하나씩 보면 다음과 같습니다.

처럼 **숫자 → 해석** 구조를 사용한다.

## 비교 기준 만들기

숫자를 하나만 보여주지 말고 가능하면 비교한다.

* 현재 vs 이전
* 현재 vs 1년 전
* A vs B
* 내 상황 vs 일반적인 상황

비교 기준이 있어야 숫자의 의미가 생긴다.

좋은 데이터는 "그래서 얼마나 다른데?"에 답한다.

따라서 가능하면 차이 / 변화율 / 순위 / 추세 / 비교 / 기준값 중 하나를 제공한다.

# 15. 독창성 생성 단계 (옛 CLAUDE.md §20)

조사 결과를 바로 글로 변환하지 않는다.

먼저 다음을 정리한다.

```text
WHAT WE KNOW
+
WHAT OTHERS EXPLAIN
+
WHAT READERS STILL DON'T UNDERSTAND
+
OUR UNIQUE EXPLANATION
```

마지막 항목이 부족하면 글을 바로 작성하지 않는다.

## "한 단계 더" 규칙

검색 결과에 이미 있는 내용을 그대로 설명하는 것으로 끝내지 않는다.

가능하면 최소 한 가지 이상의 추가 가치를 제공한다.

* 직접 계산
* 조건별 비교
* 실제 사례
* 시나리오
* 체크리스트
* 의사결정 기준
* 숫자 해석
* 독자 관점의 설명

단, 콘텐츠 성격상 필요하지 않은 요소를 억지로 넣지 않는다.

## 권장되는 가공 방식

원자료를 조사한 후 다음을 추가한다.

쉬운 설명 / 여러 자료 비교 / 숫자 재계산 / 실제 사례 제시 / 독자 관점 해석 / 장단점 비교 / 조건별 시나리오 / 체크리스트 / 표 / 계산 예시 / FAQ / 의사결정 기준

# 16. 초안 작성 순서와 독자 질문 생성 (옛 CLAUDE.md §21)

## 초안 작성 순서

```text
핵심 결론
↓
독자에게 중요한 이유
↓
사실
↓
설명
↓
숫자
↓
비교/사례
↓
분석
↓
주의사항
↓
실행 가능한 체크포인트
```

## 독자 질문 생성

조사 후 "독자가 궁금해할 질문"을 먼저 생성한다.

```text
Q1. 그래서 직장인에게 어떤 영향이 있나?
Q2. 내 대출금리는 어떻게 되나?
Q3. 지금 가입해도 되는가?
Q4. 기존 가입자는 어떻게 되나?
Q5. 세금은 얼마나 달라지나?
Q6. 누구에게 유리한가?
Q7. 반대로 불리한 사람은?
```

이 질문 중 중요한 질문을 본문에 반영한다.
