# 1. 데이터 시각화 원칙 (옛 CLAUDE.md §19)

표와 차트는 **예쁘게 만들기 위해 사용하는 것이 아니다.**

독자가 글보다 데이터를 더 쉽게 이해할 수 있을 때 사용한다.

다음 중 하나를 개선할 때만 사용한다.

이해 / 비교 / 기억 / 탐색 / 판단

그렇지 않으면 만들지 않는다.

## 좋은 차트

좋은 차트는 보는 순간 다음을 알 수 있어야 한다.

* 무엇을 비교하는지
* 어느 기간인지
* 무엇이 증가했는지
* 무엇이 감소했는지
* 차이가 얼마나 큰지
* 이 차이가 왜 중요한지

차트를 만들 때 축 단위·기간·기준일·출처를 표시하고, 데이터 왜곡과 불필요한 3D 효과를 사용하지 않는다.

## 차트 아래에는 해석을 붙인다

차트를 보여주고 끝내지 않는다.

반드시 **차트에서 봐야 할 부분**을 설명한다.

> 여기서 중요한 건 2024년 이후 물가 상승률이 계속 낮아지고 있다는 점입니다.
>
> 다만 상승률이 낮아졌다는 것은 **가격이 내려갔다는 뜻이 아니라 가격이 오르는 속도가 느려졌다는 뜻**입니다.

## 표의 원칙

표는 정보를 압축하기 위한 도구다.

다음과 같은 "번역표"를 선호한다.

| 어려운 정보 | 쉽게 보면 |
| --- | --- |
| 기준금리 | 돈의 기본 가격 |
| CPI | 생활물가가 얼마나 변했는지 |
| PER | 이익에 비해 주가가 몇 배인지 |
| 환율 | 달러 1개를 사는 데 필요한 원화 |

복잡한 내용을 설명할 때는 가능하면 **한눈에 보면** 형식의 요약표를 만든다.

| 궁금한 것 | 쉽게 말하면 |
| --- | --- |
| 금리 인하 | 돈 빌리는 비용이 낮아질 가능성 |
| 예금금리 | 받을 수 있는 이자가 줄어들 가능성 |
| 주식시장 | 기업의 자금 부담이 줄어들 수 있음 |
| 부동산 | 대출 부담이 낮아질 가능성 |

## 시각화 자동 판단

글 작성 단계에서 다음을 자동으로 판단한다.

```text
표 필요?              YES / NO
차트 필요?            YES / NO
인포그래픽 필요?      YES / NO
숫자 계산 필요?       YES / NO
용어 설명 박스 필요?  YES / NO
한눈에 보는 요약 필요? YES / NO
```

YES인 경우 `visual_plan.md`에 제작 지시사항을 기록한다.

이미지 요구사항은 다음 형식으로 생성한다.

```text
IMAGE_01
용도: 썸네일
주제: 미국 금리 인하
스타일: clean editorial illustration
비율: 16:9
텍스트: 최소화

IMAGE_02
용도: 본문 설명
주제: 금리 → 대출이자 → 소비 영향
스타일: infographic
비율: 16:9
```

# 2. 표와 숫자 사용 (옛 CLAUDE.md §39)

숫자가 여러 개 비교되는 경우 표를 적극적으로 활용한다.

예:

| 구분    | 내용 |
| ----- | -- |
| 기준금리  |    |
| 적용일   |    |
| 대상    |    |
| 주요 변화 |    |
| 출처    |    |

단, 표를 만들기 위해 숫자를 추정하지 않는다.

확인되지 않은 숫자는 빈칸으로 두거나 추가 조사를 수행한다.

```text 같은 고정폭 코드블록(<pre>)으로 계산을 보여주지 않는다.
**「안 예쁘다」** — 사용자가 ISA 글(2026-09-11 발행) 직전에 세 곳을 전부 직접 고쳤다.

계산은 원고에 ```calc 로 쓰고, md2html.js가 카드형 박스로 그린다.

| 모양 | 쓰는 곳 | 원고 |
| --- | --- | --- |
| 카드 비교형 | 여러 경우의 세금·금액 비교 | `카드:` 제목, `왼쪽 계산식 \| 세금 \| 금액` 행, 아래 `요약:` · `결론:` |

# 3. 차트 및 인포그래픽 (옛 CLAUDE.md §40)

숫자와 변화 추이를 설명하는 데 차트가 더 효과적이라면 차트를 제안한다.

차트를 만들 때 반드시 확인한다.

* 데이터 출처
* 기준일
* 단위
* 축
* 기간
* 데이터 누락 여부
* 계산 방식

시각적으로 보기 좋게 만드는 것보다 **숫자의 정확성**을 우선한다.

### 썸네일

클릭하기 전에 글의 핵심 주제를 직관적으로 이해할 수 있어야 한다.
자세한 기준은 아래 §4.2.

## 4.2 썸네일 — 목록에서 이것만 보고 클릭을 정한다 (옛 §41.2)

**본문의 첫 이미지가 곧 목록 썸네일이다.** 티스토리가 그렇게 가져간다.

**시안: `MAINSKIN/시안/글 썸네일 시안.png`** — 만들기 전에 반드시 본다.

### 본문과 썸네일은 하는 일이 다르다

| | 하는 일 |
| --- | --- |
| **본문** | 이해시킨다 |
| **썸네일** | **궁금하게 만든다** |

썸네일을 본문처럼 만들면 정확하지만 재미없다. 목록에서 아무도 안 누른다.

### 다섯 가지 구성 요소

```text
┌──────────────────────────────────────┐
│ (배지)                               │
│                        ╭─────────╮   │
│ 큰 질문형 제목          │         │   │
│ 핵심 줄만 색으로        │ 일러스트 │   │
│                        │         │   │
│ ╭────────────╮         ╰─────────╯   │
│ │ 손글씨 말풍선│                       │
│ ╰────────────╯                       │
│ ☀ 오늘의 재테크온도                   │
└──────────────────────────────────────┘
```

| 요소 | 역할 |
| --- | --- |
| **카테고리 배지** | 왼쪽 위 알약. 무슨 분야 글인지 즉시 |
| **질문형 제목** | 크게. **핵심 한 줄만** 로즈색으로 |
| **손글씨 말풍선** | **독자가 속으로 하는 말.** 궁금증을 만드는 장치 |
| **일러스트** | 화면의 3분의 1 이상. 글자만 있으면 딱딱하다 |
| **브랜드 한 줄** | ☀ 오늘의 재테크온도 |

### 제목은 넣되, 같은 뜻 다른 문장으로

**썸네일에 제목을 넣는다.** 카카오톡 공유나 핀터레스트로 나갈 때는 이미지만 돌기 때문에,
글자가 없으면 무슨 글인지 알 수 없다.

다만 **글 제목을 그대로 옮겨 적지 않는다.** 목록에서는 제목이 옆에 글자로 또 나온다.
같은 문장이 두 번 보이면 얻는 정보가 없다.

```text
글 제목 :  기준금리 3% 됐는데, 내 대출이자는 「왜」 아직 「그대로」일까?
썸네일  :  금리 올랐다는 뉴스,  내 통장엔     「언제」  「도착」할까?
                                              └── 묻는 틀을 바꾼다
```

### 틀을 바꾸는 방법

| 바꾸는 것 | 예 |
| --- | --- |
| **묻는 말** | 왜 → 언제 / 얼마나 / 어디서 |
| **주어** | 내 대출이자 → 내 통장 (더 손에 잡히는 말로) |
| **동사** | 그대로다 → 도착한다 (본문의 비유를 끌어온다) |

같은 것을 묻되 **다른 각도에서** 묻는다.
글 제목이 「왜 안 오르나」면 썸네일은 「언제 오르나」로 묻는 식이다.

**답을 바꾸는 게 아니라 질문을 바꾸는 것이다.** 여전히 답은 주지 않는다.

### 말풍선이 핵심이다

썸네일에서 클릭을 만드는 건 제목이 아니라 **말풍선**이다.
독자가 자기 상황을 알아보게 만든다.

* 「이번 달 이자, 지난달이랑 똑같던데…?」
* 「환급받는다더니 왜 이것밖에 안 나오지?」
* 「여러 개 사야 하는 걸까?」

**답이 아니라 되묻기다.** 설명하지 않는다.

### 글꼴

**학교안심 알림장**을 쓴다. 손글씨 느낌이면서 OFL이라 상업 이용이 자유롭다.
`이미지렌더.js` 가 절대경로로 주입하므로 소스에는 `font-family:'알림장'` 만 쓴다.

라이선스를 확인하지 않은 글꼴은 쓰지 않는다 (CLAUDE.md §66.11 RED). `MAINSKIN/글꼴.md` 참고.

### 목록 크기에서 읽히는가

썸네일은 **폭 320px(모바일 200px)로 보인다.** 원본의 1/5이다.
만들고 나면 반드시 그 크기로 줄여서 본다.

| 원본 글자 | 목록에서 | 판정 |
| --- | --- | --- |
| 98px 이상 | 20px 이상 | 잘 읽힘 |
| 42px | 8px | 분위기만 (말풍선은 이 정도라도 된다) |
| 30px 이하 | 6px | 못 읽음. 꼭 필요한 것만 |

**일러스트는 작아져도 형태가 남는다.** 그래서 글자보다 일러스트가 유리하다.

### 답을 다 주지 않는다

| | |
| --- | --- |
| **나쁨** | 「내 이자는 11월에 오릅니다」 — 답을 줘버려 열 이유가 사라진다 |
| **나쁨** | 「① 코픽스는 한 달에 한 번 ② 금리 바뀌는 날」 — **이유를 이름까지 대면 그것도 답이다** |
| **좋음** | 말풍선으로 되묻기 — 「이번 달 이자, 지난달이랑 똑같던데…?」 |

**확인법**: 썸네일 문구를 본문 `[정답]` 박스와 나란히 놓고 읽어본다.
같은 말을 하고 있으면 답을 준 것이다.

「답이 있다는 것만 보여준다」고 생각하면서 **이유를 하나씩 열거하기 쉽다.**
열거하는 순간 그게 답이다.

### 가정을 단정으로 쓰지 않는다

본문에서 「예를 들어」로 든 숫자를 썸네일에 사실처럼 적지 않는다.
아래에 작게 단서를 달아도 **그 글씨는 목록에서 안 읽힌다.**
단서가 필요한 숫자라면 애초에 넣지 않는다.

### 로고를 넣지 않는다

온도계 마크는 **파비콘**이다. `MAINSKIN/images/icon-master.png`
브라우저 탭과 검색 결과에서 글 옆에 이미 붙는다. 썸네일에 또 그리면 중복이다.

특히 **원본 파일을 쓰지 않고 코드로 다시 그리지 않는다.** 비율이 미묘하게 달라져
같은 마크의 서로 다른 버전이 두 개 돌게 된다.

일러스트는 로고와 다르다. 그 글의 내용을 그린 그림은 넣는다.

### 하지 말 것

* 글자를 빽빽하게 채우기 — 목록에서는 작게 보인다
* 본문에 없는 숫자·주장 넣기 (`md2html.js` 정합성 검사가 잡는다)
* 자극적인 표현으로 클릭 유도 (`00_브랜드/ADSENSE.md` §2.8)
