# SEARCH MAP — SEO · AEO · GEO

> SEARCH MAP은 **검색 구조만** 담당한다.
> 말투, 카테고리, 색상, 실제 출처 표기, 사실검증, 계산 표시 등 다른 문서에 이미 있는 규칙은 여기서 다시 정의하지 않는다.

---

# 1. 역할

`CONTENT_ARCHITECT`가 설계한 콘텐츠를 검색자가 발견하고, 질문에 답을 얻고, 검색/생성형 시스템이 사실과 문맥을 명확하게 이해하도록 만든다.

```text
독자의 실제 질문
↓
검색 의도
↓
SEO
↓
AEO
↓
GEO
↓
MONEYWEATHER의 쉬운 설명
```

---

# 2. SEARCH INTENT

검색어보다 **검색자가 원하는 것**을 판단한다.

| 유형 | 독자의 질문 |
|---|---|
| KNOW | 이게 뭔가? |
| WHY | 왜 그런가? |
| PROBLEM | 왜 내 상황은 다른가? |
| CALCULATE | 나에게 얼마인가? |
| COMPARE | 무엇이 다른가? |
| ACTION | 그래서 무엇을 확인하거나 판단해야 하는가? |

검색 의도는 CONTENT_ARCHITECT의 LEVEL과 다른 축이다.

예:

```text
LEVEL 2 CURRENT ISSUE
“올해 주식시장 좋다는데 왜 내 계좌는 마이너스일까?”

검색 의도
= PROBLEM + WHY
```

---

# 3. SEO

SEO에서 정하는 것:

- 핵심 검색 질문
- 메인 키워드
- 관련 검색어
- 롱테일 질문
- 제목 방향
- 질문형 H2/H3
- 검색자가 클릭할 이유

## 원칙

- 키워드를 반복하기 위해 문장을 만들지 않는다.
- 제목과 본문의 검색 의도를 일치시킨다.
- 실제 사람이 검색할 법한 표현을 사용한다.
- 검색량만으로 주제를 결정하지 않는다.
- 이미 작성된 콘텐츠와 검색 의도가 겹치면 질문을 다르게 만든다.

---

# 4. AEO

AEO의 목표는 모든 글을 FAQ로 만드는 것이 아니다.

> **독자가 질문했을 때 핵심 답을 빠르게 찾을 수 있게 하는 것**이다.

핵심 질문은 다음 구조로 설계한다.

```text
질문
↓
첫 문장의 직접 답변
↓
짧은 이유
↓
필요한 설명
↓
숫자·예시·비교
```

### 원칙

- 결론을 뒤로 미루지 않는다.
- 질문형 소제목은 실제 질문을 사용한다.
- 답변 단위만 떼어 읽어도 의미가 유지되게 한다.
- FAQ는 실제 질문이 있을 때만 사용한다.

실제 `[정답]`, `[문답]`, 마무리 형태는 `글쓰기톤.md`를 따른다.

---

# 5. GEO

GEO는 “AI에 인용되게 만들기”보다 **정보가 잘못 잘려도 의미가 유지되도록 만드는 것**에 초점을 둔다.

GEO에서 확인할 것:

- 정보의 주어가 명확한가?
- 무엇이 무엇에 영향을 주는지 관계가 명확한가?
- 날짜·기준일이 필요한 정보인가?
- 현재와 과거가 구분되는가?
- 사실과 해석이 구분되는가?
- 핵심 답변 문장이 독립적으로 성립하는가?
- 기관·상품·제도·지표의 이름과 관계가 명확한가?

### 중요

실제 출처 우선순위, 인라인 출처 방식, 기준일 작성, 사실관계 검증, 정책 확정 여부, 숫자 검증 등은 `CLAUDE.md`를 따른다.

`CLAUDE.md`에는 이미 GEO에 해당하는 규칙이 존재한다. 예를 들어 인라인 출처, 기준일, 원자료 우선, 전문용어 정의, 단정하지 않기, 최신·과거 구분 등은 별도 GEO 규칙으로 복제하지 않는다.

---

# 6. ENTITY 구조

필요한 경우 중요한 기관·제도·지표의 관계를 설명한다.

```text
한국은행
 ↓ 결정
기준금리
 ↓ 영향
시장금리
 ↓ 영향
예금금리 / 대출금리
 ↓
가계의 이자 부담
```

단어를 나열하는 것이 아니라 **관계가 무엇인지** 설명한다.

---

# 7. 숫자·비교·FAQ

검색을 위해 숫자나 FAQ를 억지로 추가하지 않는다.

독자의 이해에 필요한 경우만 사용한다.

```text
숫자 → 의미 → 실제 돈
비교 → 같은 기준 → 차이의 의미
질문 → 직접 답 → 필요한 설명
```

실제 계산 방식은 `CLAUDE.md` §17, 계산 카드 표시법은 `00_브랜드/시각자료.md` §2.1을 따른다.

# 9. 금지

SEARCH MAP에서 다음을 새로 정의하지 않는다.

- 글쓰기 말투
- 문장 길이 규칙
- 고정된 글 앞뒤 구조
- 색상
- 카테고리
- 출처 표기 형식
- 사실관계 검증 절차
- 계산 박스 형식
- 썸네일 제작 규칙
- 내부링크 실행 규칙

각각 `글쓰기톤.md`, `색상.md`, `시각자료.md`, `카테고리.md`, `CLAUDE.md`를 따른다.

# 10. 제목 생성 시스템 (옛 CLAUDE.md §13)

제목을 하나만 생성하지 않는다.

가능하면 다음 유형으로 후보를 만든다.

### 정보형

"○○란? 처음 보는 사람도 이해하는 핵심 정리"

### 문제해결형

"○○ 때문에 돈이 달라질까? 꼭 확인해야 할 5가지"

### 비교형

"○○ vs ○○, 직장인이라면 무엇이 다를까?"

### 숫자형

"월 ○만원 기준으로 보면 ○○는 얼마나 달라질까?"

### 시점형

"2026년 ○○, 지금 달라진 핵심 내용 정리"

그중

**검색 의도 + 정보 명확성 + 클릭 이유**

가 가장 좋은 제목을 선택한다.

---

# 11. 제목 작성 원칙 (옛 CLAUDE.md §37)

제목은 검색성과 클릭성을 고려하되 낚시성 제목을 사용하지 않는다.

좋은 제목은 독자의 질문을 직접 건드린다.

### 예

* 기준금리 내렸다는데, 내 대출금리도 바로 내려갈까?
* ISA가 좋다는데 도대체 뭐가 좋은 걸까?
* 배당률 10% ETF, 정말 1년에 10% 받는 걸까?
* 공시가격이 올랐는데 내 세금도 같이 오를까?
* 청약에서 무주택으로 인정되는 집은 따로 있을까?

---

# 12. SEO 원칙 (옛 CLAUDE.md §38)

SEO를 고려하되 검색엔진을 위한 글이 사람이 읽기 어려운 글이 되지 않도록 한다.

키워드는 자연스럽게 사용한다.

억지로 동일 키워드를 반복하지 않는다.

제목·소제목·본문·FAQ 등에서 독자가 실제로 검색할 표현을 활용한다.

검색량만 보고 주제를 결정하지 않는다.

**검색 의도와 독자에게 제공하는 실제 가치가 우선이다.**


---

## 12.1 SEO / AEO / GEO — 세 계층 (옛 §38.1)

검색엔진만 보고 쓰지 않는다. 요즘은 사람이 검색창에 치는 것보다
**AI에게 물어보고 그 답만 읽고 끝내는 경우**가 늘고 있다.

그래서 글 하나에 세 가지를 같이 넣는다.

| 계층 | 무엇을 위한 것인가 |
| --- | --- |
| **SEO** | 검색엔진이 **이 글이 무엇에 관한 글인지** 알게 한다 |
| **AEO** | 누가 물었을 때 AI가 **이 글에서 답을 뽑아갈 수 있게** 한다 |
| **GEO** | AI가 이 글을 **믿을 만한 정보원으로** 보게 한다 |

### 글의 뼈대

```text
독자가 실제로 묻는 질문        ← 제목
      ↓
한 문장 정답  [정답]           ← AEO. 스크롤 전에 답을 준다
      ↓
쉬운 설명 + 근거·출처          ← GEO
      ↓
숫자를 실제 생활비로 번역
      ↓
표 · 그림
      ↓
자주 묻는 질문  [문답]         ← AEO
      ↓
오늘 할 것  [체크]             ← 읽고 끝나지 않게
```

### SEO — 검색엔진이 알아보게

* **제목의 질문 하나에만 답한다.** 본문이 옆으로 번지면 이 글이 무엇에 관한
  글인지 흐려진다. 번진 부분은 **별도 글로 뗀다** (CLAUDE.md §62 중복 판정과 함께 본다)
* **소제목을 질문형으로 쓴다.** 검색창에 그대로 쳐볼 만한 문장이어야 한다
  ("일단 기준금리가 뭔지부터" → "기준금리가 뭔가요?")
* 키워드를 억지로 반복하지 않는다 (`00_브랜드/ADSENSE.md` §2.7)

### AEO — AI가 답을 뽑아갈 수 있게

* **글 앞부분에 `[정답]` 박스**를 둔다. 제목의 질문에 1~3문장으로 답한다
* **정답 박스와 FAQ의 각 항목은 단독으로 읽혀야 한다.**
  "위에서 말했듯이", "앞서 본 것처럼" 같은 앞뒤 의존 표현을 그 안에서 쓰지 않는다.
  AI는 문맥을 잘라 인용하기 때문이다
* **`[문답]` FAQ**를 넣는다. 질문 하나에 답 하나가 짝으로 떨어지게 쓴다
* 조건과 숫자를 명확히 적는다 ("빨라도 10월, 대출 조건에 따라 그 이후")

### GEO — 믿을 만한 정보원으로 보이게

이미 있는 규칙들이 그대로 GEO다. 새로 할 것이 아니라 **지키면 된다.**

| GEO 요구 | 이미 있는 규칙 |
| --- | --- |
| 출처 명시 | CLAUDE.md §49.1 인라인 출처 |
| 기준일 명시 | CLAUDE.md §32 최신 정보 처리 |
| 원자료 우선 | CLAUDE.md §26.2 출처 우선순위 |
| 전문용어 정의 | CLAUDE.md §14, 글쓰기톤.md §7 |
| 단정하지 않기 | CLAUDE.md §29 권장 표현 |
| 최신·과거 구분 | CLAUDE.md §32.1 3개월 기준선 |

### 하지 말 것

* **없는 링크를 만들지 않는다.** `href="#"` 같은 자리표시자를 발행본에 남기지
  않는다 (`00_브랜드/ADSENSE.md` §2.1). 내부 링크는 그 글이 실제로 발행된 뒤에 넣는다
* FAQ를 개수 채우려고 늘리지 않는다. 독자가 실제로 물을 것만 넣는다 (`00_브랜드/ADSENSE.md` §2.7)
* 정답 박스를 요약으로 쓰지 않는다. **답**을 쓴다

### 티스토리에서 하나 더

티스토리는 목록과 홈의 글 요약을 **본문 맨 앞에서 긁어간다.**
그래서 글의 첫 두세 문장이 곧 목록에 보이는 문장이다.
면책이나 제목 반복이 아니라 **독자가 열어볼 이유**가 거기 있어야 한다 (CLAUDE.md §49.3).

# 13. SEO 메타데이터와 발행 패키지 (옛 CLAUDE.md §61)

## SEO 메타데이터

가능하면 다음을 자동 생성한다.

```text
SEO_TITLE:
META_DESCRIPTION:
PRIMARY_KEYWORD:
SECONDARY_KEYWORDS:
SEARCH_INTENT:
SLUG:
TAGS:
CATEGORY:
```

## Tistory 발행 패키지

최종 발행용 파일에는 가능하면 다음을 포함한다.

```text
TITLE

META DESCRIPTION

CATEGORY

TAGS

THUMBNAIL PROMPT

ARTICLE BODY

TABLES

CHARTS

IMAGE PLACEMENT

IMAGE ALT TEXT

SOURCE SECTION

RELATED POSTS

DISCLAIMER
```
