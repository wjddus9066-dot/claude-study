# 오늘의 재테크온도 — MASTER CLAUDE.md

## 0. PROJECT IDENTITY

블로그명: 오늘의 재테크온도
블로그 주소: moneyweather
핵심 독자: 20~40대 직장인
주요 주제:
- 경제
- 투자
- 부동산
- 세금
- 금융
- 일상에서 실제로 마주치는 돈 문제

블로그의 핵심 목표:

"어려운 경제·금융 정보를 초보자의 눈높이에서 쉽게 이해시키고,
읽고 나서 실제 생활에 적용할 수 있게 만드는 것."

---

# 1. ABSOLUTE PRIORITY

모든 콘텐츠에서 가장 중요한 원칙은 다음과 같다.

## "어려워지면 안 된다."

정보를 많이 넣는 것보다 독자가 이해하는 것이 우선이다.

전문가에게 정확한 글보다
비전문가가 끝까지 읽고 이해할 수 있는 글을 만든다.

다음 우선순위를 따른다.

1. 이해하기 쉬운가?
2. 정확한가?
3. 독자의 질문에 답하는가?
4. 실제 생활에 도움이 되는가?
5. 검색과 AI가 내용을 정확하게 이해할 수 있는가?
6. 시각적으로 이해하기 쉬운가?

SEO를 위해 문장을 억지로 어렵게 만들지 않는다.

정보량을 늘리기 위해 불필요한 전문용어를 추가하지 않는다.

---

# 2. WRITING PHILOSOPHY

독자는 경제 전문가가 아니다.

따라서 다음과 같은 독자를 기본값으로 가정한다.

- 경제 용어를 잘 모른다.
- 숫자와 지수를 보면 부담을 느낄 수 있다.
- 긴 설명을 싫어한다.
- "그래서 나한테 무슨 의미인데?"가 가장 궁금하다.
- 어려운 글은 중간에 이탈한다.

따라서 모든 글은 다음 흐름을 기본으로 한다.

질문
→ 즉답
→ 쉬운 설명
→ 비유
→ 실제 개념
→ 숫자 번역
→ 시각화
→ 내 상황에 적용
→ 행동/체크포인트
→ 관련 콘텐츠

# 3. SEO / AEO / GEO

SEO, AEO, GEO는 HTML 장식이나 키워드 삽입 기술로 취급하지 않는다.

글의 내용 자체에 자연스럽게 통합한다.

## SEO

- 검색 의도를 먼저 파악한다.
- 제목은 독자의 실제 질문과 문제를 반영한다.
- 핵심 키워드를 자연스럽게 사용한다.
- H2/H3는 독자가 실제로 궁금해할 질문 중심으로 구성한다.
- 과도한 키워드 반복을 금지한다.
- 관련 글이 있으면 내부 링크를 활용한다.
- 검색 결과에서 제목만 보아도 글의 답을 예상할 수 있도록 한다.

## AEO

독자가 질문했을 때 AI가 글의 핵심 답변을 정확하게 추출할 수 있도록 작성한다.

- 글 초반에 핵심 답변을 명확하게 제시한다.
- 질문형 소제목을 적극 활용한다.
- 중요한 질문에는 1~2문장으로 바로 답할 수 있는 문장을 둔다.
- 핵심 숫자와 조건을 명확하게 표현한다.
- 표, 목록, FAQ 등을 활용한다.
- 문맥에서 잘려 나가도 의미가 유지되는 문장을 만든다.

## GEO

정보의 근거와 맥락을 명확하게 한다.

- 가능한 경우 1차 출처를 우선한다.
- 출처를 명확하게 표시한다.
- 기준일/공시일/조회일을 구분한다.
- 현재 정보와 과거 정보를 혼동하지 않는다.
- 사실과 해석을 구분한다.
- 근거 없는 단정은 하지 않는다.
- AI가 일부 문장만 인용해도 의미가 왜곡되지 않도록 작성한다.

# 4. EASY_EXPLAINER

모든 글에는 EASY_EXPLAINER 원칙을 적용한다.

## 기본 규칙

1. 어려운 용어를 처음부터 연속해서 사용하지 않는다.
2. 쉬운 말로 먼저 설명하고 전문용어를 붙인다.
3. 한 문단에는 하나의 핵심 개념만 전달한다.
4. 긴 문단을 피한다.
5. 한 문장이 지나치게 길어지지 않도록 한다.
6. 설명 후에는 "그래서 무슨 뜻인지"를 알려준다.
7. 가능하면 독자가 실제 생활에서 접하는 상황으로 연결한다.

---

# 5. 비유를 통한 설명

복잡한 경제·금융 개념은 적절한 비유를 적극적으로 활용한다.

예:

- 기준금리 → 경제의 큰 수도꼭지
- 대출금리 → 최종 가격표
- COFIX → 은행의 자금 조달 원가표
- 변동금리 → 일정 기간마다 다시 확인하는 가격표

단, 비유가 실제 제도와 완전히 동일한 것처럼 표현하지 않는다.

반드시 다음 구조를 따른다.

[어려운 개념]
↓
[쉬운 비유]
↓
[실제 개념으로 다시 설명]
↓
[독자의 생활에 적용]

비유는 재미를 위한 장식이 아니라
"머릿속에 구조를 그려주는 도구"로 사용한다.

# 6. DATA_TRANSLATOR

숫자를 그대로 보여주는 것을 금지한다.

가능한 경우 다음 단계로 번역한다.

원래 숫자
→ 무엇을 의미하는가
→ 실제 금액/비율
→ 독자의 생활에 어떤 영향을 주는가

예:

"금리가 0.5%p 올랐다."

에서 끝내지 않는다.

가능하면:

"3억원을 빌렸다면 단순 계산상
연간 약 150만원,
월평균 약 12만5천원의 이자 차이가 생길 수 있습니다."

처럼 설명한다.

단, 실제 금융상품의 계산에는
대출 조건, 상환 방식, 금리 적용 방식 등에 따라 차이가 있음을 명확히 한다.

---

# 7. VISUAL_PLANNER

모든 글은 "글만으로 설명하는 것이 가장 좋은가?"를 먼저 판단한다.

복잡한 개념은 가능한 경우 시각화한다.

활용 가능한 형태:

- 개념도
- 흐름도
- 비교표
- 숫자 비교
- 차트
- 인포그래픽
- 단계별 설명 이미지
- 구조도
- 타임라인

중요:

시각화는 장식이 아니다.

"이것을 글보다 그림으로 보여주면 더 빨리 이해할 수 있는가?"

를 기준으로 판단한다.

표/차트를 넣을 경우 반드시 아래 중 하나를 함께 제공한다.

- 핵심 해석
- 한 줄 요약
- 독자가 주목할 숫자
- 생활에 미치는 의미

---

# 8. CONTENT_ARCHITECT

새로운 주제를 작성하기 전에
독자가 이해하기 위해 필요한 선행 개념을 확인한다.

예:

"기준금리가 내려갔는데 내 대출금리는 왜 그대로일까?"

필요한 개념:

기준금리
→ 은행 조달비용
→ 지표금리
→ COFIX/금융채
→ 은행 가산금리
→ 대출금리
→ 실제 금리 재산정일

이미 관련 기초 글이 있다면 내부 링크한다.

기초 글이 없다면:

- 현재 글에서 짧게 설명하거나
- 별도의 기초 콘텐츠 후보로 기록한다.

모든 기초 개념을 무조건 별도 글로 만들지 않는다.

---

# 9. FACT_CHECKER

경제·금융·세금·부동산 정보는 정확성을 우선한다.

특히 다음을 확인한다.

- 날짜
- 금액
- 금리
- 세율
- 한도
- 자격요건
- 정책 변경
- 적용 시점
- 통계 기준
- 출처

확인되지 않은 정보를 사실처럼 작성하지 않는다.

출처가 필요한 정보에는 출처를 표시한다.

# 10. 글의 기본 구조

가능하면 다음 구조를 사용한다.

## 제목

독자의 실제 질문이나 문제를 반영한다.

## 도입

독자가 실제로 겪는 상황을 제시한다.

## 핵심 답변

가장 먼저 답한다.

## 왜 그런가?

핵심 원인을 쉽게 설명한다.

## 비유

복잡한 구조를 머릿속에 그릴 수 있도록 설명한다.

## 개념 이해

필요한 전문용어를 설명한다.

## 표/차트/시각화

복잡한 정보를 한눈에 정리한다.

## 숫자 번역

실제 금액이나 생활 영향으로 바꾼다.

## 내 상황에 적용

독자가 자신의 상황을 대입할 수 있도록 한다.

## 오늘 확인할 것

실제로 할 수 있는 행동을 제시한다.

## 관련 콘텐츠

다음에 읽으면 좋은 글을 연결한다.

# 11. 금지사항

다음과 같은 글을 만들지 않는다.

- 전문가가 전문가에게 쓰는 듯한 문체
- 어려운 용어의 연속 사용
- 긴 문단
- 의미 없는 숫자 나열
- 표만 던지고 해석하지 않는 글
- 차트만 넣고 의미를 설명하지 않는 글
- SEO 키워드를 억지로 반복하는 글
- 근거 없는 확정적 표현
- 출처 없는 최신 정보
- 내용과 관계없는 이미지
- 장황한 서론
- 결론까지 가야 핵심 답을 알 수 있는 글
