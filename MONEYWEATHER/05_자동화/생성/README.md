# 05_자동화/생성 — 발행용 변환 도구

## md2html.js — 초안 마크다운 → 발행용 HTML

```bash
node 05_자동화/생성/md2html.js <draft.md 경로>
```

두 파일이 만들어진다.

| 파일 | 용도 |
| --- | --- |
| `article.html` | 브라우저에서 바로 보이는 단독 페이지 |
| `article-tistory.html` | Tistory HTML 모드 붙여넣기용 조각 |

발행본에서 자동으로 빠지는 것: 상단 메타 블록(상태/작성일/카테고리), HTML 주석.

---

## 이미지 삽입 — images.json

초안과 같은 폴더에 `images.json`을 두면 그 위치에 그림이 들어간다.

```json
[
  {
    "after": "",
    "src": "../../../04_이미지/2026-09-05_기준금리3.00_대출금리_26.09.11/01_썸네일.png",
    "alt": "대체 텍스트"
  },
  {
    "after": "<p>그림으로 보면 이렇습니다.</p>",
    "src": "../../../04_이미지/2026-09-05_기준금리3.00_대출금리_26.09.11/02_전달경로.png",
    "alt": "대체 텍스트",
    "caption": "그림 아래 설명"
  }
]
```

- `after`가 비어 있으면 글 맨 앞(대표 이미지)
- `after`는 **변환된 HTML에 등장하는 고유 문자열**이다. 본문을 고치면 앵커도 같이 고쳐야 한다
- 앵커를 못 찾으면 `[건너뜀]` 경고가 뜬다. 무시하지 말 것

## 정합성 검사 (자동 실행)

변환할 때마다 아래 두 가지를 검사한다.
**본문만 고치고 이미지를 안 고치는 실수**가 실제로 두 번 나서 만들었다.

### 1. 금지 표현 — `[정합성 경고]`

`00_브랜드/글쓰기톤.md` §5.1의 목록을 읽어서 본문과 이미지 소스를 모두 검사한다.
목록을 고칠 때 이 스크립트는 건드리지 않아도 된다.

```
[정합성 경고]
  X 본문에 금지 표현: "쉽게 말하면"
  X 2026-09-05_img03_fixvar.html 에 금지 표현: "정리하면 이렇습니다"
```

### 2. 이미지에만 있는 숫자 — `[확인 필요]`

본문에 없는 숫자가 이미지에 있으면 알려준다.
본문에서 뺀 수치나 주장이 그림에만 살아남는 경우를 잡는다.

```
[확인 필요] 이미지에만 있는 숫자입니다. 본문과 다른 말을 하고 있지 않은지 보세요.
  · 2026-09-05_img03_fixvar.html — 본문에 없는 숫자: 0.41%포인트, 0.5%p
```

**주의**: 그래프 축 눈금처럼 정상인 경우도 걸린다. 자동 판단이 아니라 사람이 보라는 알림이다.

### 검사 대상 찾는 방법

초안 폴더와 **같은 이름**의 이미지 폴더에서 `_소스/*.html`을 찾는다.

```text
03_콘텐츠/초안/2026-09-07_ISA_직장인_실제혜택/draft.md
                └──────────── 같은 이름 ────────────┐
04_이미지/2026-09-07_ISA_직장인_실제혜택/_소스/*.html
```

그래서 **이미지 폴더 이름은 초안 폴더 이름과 정확히 같아야** 한다.

출처 표기줄(`<div class="src">`)은 검사에서 제외한다.
본문은 쉽게 쓰더라도 **출처는 정확해야 하기 때문**이다 (CLAUDE.md §28, §49).

## 알아둘 것

### 이미지를 다시 만들 때

Chrome 헤드리스가 **한글 경로에 `--screenshot` 쓰기를 조용히 실패**한다.
에러도 안 나고 예전 파일이 그대로 남으므로, 임시 경로에 만든 뒤 복사해야 한다.

```bash
CH="/c/Program Files/Google/Chrome/Application/chrome.exe"
TMP="<스크래치패드 경로>"
cp 04_이미지/2026-09-05_기준금리3.00_대출금리_26.09.11/_소스/02_전달경로.html "$TMP/x.html"
"$CH" --headless --disable-gpu --hide-scrollbars --window-size=1600,900 \
      --screenshot="$TMP/x.png" "file:///$(cygpath -m "$TMP/x.html")"
cp "$TMP/x.png" 04_이미지/2026-09-05_기준금리3.00_대출금리_26.09.11/02_전달경로.png
```

만든 뒤에는 **반드시 눈으로 확인**한다. 파일 크기만 보면 안 바뀐 걸 못 잡는다.

### 코드블록의 특수문자

①②③ 같은 동그라미 숫자는 고정폭 폰트에서 깨진다.
`[1단계]` 처럼 쓰는 게 안전하다.

### Tistory에 붙여넣을 때

`article-tistory.html`의 이미지 경로는 로컬 상대경로라 Tistory에서 작동하지 않는다.
붙여넣은 뒤 깨진 이미지 자리에 에디터로 직접 업로드해야 한다.
위치와 캡션은 이미 잡혀 있으므로 파일만 갈아끼우면 된다.

## 티스토리에 발행하는 순서

`article-tistory.html` 을 **그대로 붙여넣으면 이미지가 안 나온다.**
그 안의 이미지 경로는 내 컴퓨터 안의 경로라서, 티스토리에는 그런 파일이 없다.

이미지를 티스토리에 먼저 올리고, 받은 주소로 갈아끼워야 한다.

**같은 명령을 두 번 돌린다.** 중간에 파일 하나에 붙여넣는 게 전부다.

```bash
# 1. 올릴 순서를 알려주고 「붙여넣기.txt」를 만들어 준다
node 05_자동화/생성/이미지주소적용.js <초안폴더>

# 2. 티스토리 글쓰기에서 그 순서대로 이미지를 올린다
#    HTML 모드로 바꿔서 [##_Image|...] 부분을 통째로 복사한다

# 3. <초안폴더>/붙여넣기.txt 를 열어서 붙여넣고 저장한다
#    ※ 이미지주소적용.js 에 붙여넣는 게 아니다

# 4. 같은 명령을 한 번 더. 이번엔 붙여넣기.txt 를 읽는다
node 05_자동화/생성/이미지주소적용.js <초안폴더>

# 5. 나온 article-tistory-발행.html 을 통째로 붙여넣는다
```

### 왜 파일로 받나

매크로는 여러 줄이고 안에 큰따옴표와 중괄호가 들어 있다.
터미널에 따옴표로 감싸 넣으면 셸이 먹어버리거나 줄이 잘린다.
메모장에 붙여넣듯 파일에 넣는 쪽이 실수가 없다.

`#` 으로 시작하는 줄은 무시하므로 안내문을 지우지 않아도 된다.
발행이 끝나면 `붙여넣기.txt` 는 지워도 된다. 다음에 또 만들어준다.

예전 방식(`--붙여넣기 '내용'`)도 그대로 동작한다.

주소를 하나하나 넣지 않고 HTML 덩어리째 넣어도 된다. 매크로를 알아서 뽑는다.

**개수가 맞지 않으면 멈춘다.** 순서가 어긋난 채로 발행되는 것보다 낫다.

### 좁은 스킨에서도 안 잘리게

티스토리 스킨은 본문 칸이 600~800px로 좁은 경우가 많다.
그래서 발행용 HTML은 좁은 칸에서 잘리지 않도록 만든다.

* 표 머리줄에 `white-space:nowrap` 을 걸지 않는다 — 걸면 칸을 넘겨 잘린다
* 표·코드블록·그림에 `max-width:100%` 를 준다
* 코드블록은 본문보다 작은 글씨로 (`.86rem`)

620px 칸에 넣고 넘치는 요소가 없는지 확인했다.

**본문 양옆에 여백이 많이 남는 건 스킨 설정이다.** 글 HTML로는 못 바꾼다.
티스토리 관리 → 꾸미기 → 스킨 편집에서 본문 너비를 조정한다.

## 만들어지는 파일 세 개

```text
draft.md
   ↓  md2html.js
article.html          브라우저에서 바로 읽는 완성본
article-tistory.html  티스토리 HTML 모드에 붙여넣는 것  ← 발행용
미리보기.md            깃허브에서 이미지까지 같이 보는 것
```

### 미리보기.md 가 왜 필요한가

**깃허브는 HTML을 화면으로 그려주지 않는다.**
`article.html` 을 눌러도 코드만 보이고 그림은 안 나온다.

마크다운은 그려주므로, 이미지를 끼워 넣은 마크다운을 하나 더 만든다.
`draft.md` 에서 자동으로 만들기 때문에 원고와 어긋나지 않는다.
**직접 고치지 않는다.** 고치면 다음 실행 때 덮어써진다.

본문 마커는 깃허브가 알아보는 형태로 바뀐다.

| 원고 | 미리보기 |
| --- | --- |
| `[안내]...[/안내]` | `> [!NOTE]` 인용 상자 |
| `[출처] ...` | `<sub>` 작은 글씨 |
| `[FOOTER]` | `---` 구분선 |

## 이미지렌더.js — 그림 소스 → PNG

```bash
node 05_자동화/생성/이미지렌더.js            # 04_이미지/*/_소스/*.html 전부
node 05_자동화/생성/이미지렌더.js 2026-09-07  # 경로에 그 글자가 들어간 것만
```

`04_이미지/<글폴더>/_소스/*.html` 은 읽는 문서가 아니라 **그림을 그리는 도면**이다.
선 좌표와 막대 높이를 직접 잡아 Chrome으로 PNG를 찍는다.
그래서 마크다운으로 대체할 수 없다.

### 새 그림을 만들 때

소스 맨 위에 **어디로 나갈지**를 적는다. 이게 없으면 건너뛴다.

```html
<!doctype html>
<meta charset="utf-8">
<!-- @출력 04_이미지/2026-09-05_기준금리3.00_대출금리_26.09.11/03_코픽스추이.png -->
<!-- @크기 1600x900 -->
```

색은 **직접 적지 않고** 변수로 쓴다.

```css
body { background:var(--ivory); color:var(--navy); }
```

SVG는 주의할 게 하나 있다. `fill="var(--navy)"` 처럼 **속성으로 쓰면 안 먹는다.**
`style` 로 옮겨야 한다.

```html
<circle cx="86" cy="336" r="44" style="fill:var(--pink)"/>
```

쓸 수 있는 변수 이름은 `05_자동화/팔레트.js` 에 있다.
`navyD` 는 `--navy-d` 가 된다.

### 한글 경로 문제

Chrome은 한글이 섞인 경로로 `--screenshot` 을 쓰면 **오류 없이 조용히 실패한다.**
예전 파일이 그대로 남아서 바뀐 줄 알기 쉽다.
`이미지렌더.js` 는 임시폴더에 찍고 복사하는 방식으로 이걸 피한다.

직접 Chrome을 부를 일이 있으면 같은 방식을 쓴다.

## 색은 어디서 오나

브랜드 색은 `05_자동화/팔레트.js` 한 곳에만 있다. (설명: `00_브랜드/색상.md`)

로고 이미지에서 픽셀을 직접 세어 뽑은 색이다.

```text
                     팔레트.js
                         │
         ┌───────────────┴───────────────┐
     md2html.js                     이미지렌더.js
         │                               │
    STYLE 한 벌                    var(--navy) 주입
     ┌───┴────┐                          │
article.html  article-tistory.html   04_이미지/**.png
(<style>)     (태그마다 style="")
```

색을 바꾸려면 `팔레트.js`만 고치고 두 명령을 다시 돌린다.
**HTML에 색을 직접 적지 않는다.** 글이든 그림이든 마찬가지다.

### 티스토리는 왜 인라인인가

티스토리 HTML 모드에는 `<style>` 블록을 같이 넣을 수 없다.
넣어도 스킨이 지우거나 스킨 CSS와 충돌한다.

그래서 `inlineStyles()`가 태그마다 `style=""`을 직접 박는다.
붙여넣기만 하면 스킨 설정과 상관없이 같은 모양으로 나온다.

가상요소(`::before`)와 미디어쿼리는 인라인으로 넣을 수 없어서
읽기용 `article.html`에만 들어간다. 체크리스트 네모가 여기 해당한다.

## 앞머리 안내 박스 — [안내]

글 맨 앞(제목 바로 아래)에 넣는 작은 회색 박스다.
`[안내]` 와 `[/안내]` 사이에 쓴 내용이 `<aside class="pre-note">`로 변환된다.

```markdown
[안내]
**읽기 전에 참고해주세요**

이 글의 금리·이자 계산은 이해를 돕기 위한 대략적인 계산입니다.

특정 금융상품의 가입이나 갈아타기를 권유하는 글은 아닙니다.
[/안내]
```

빈 줄로 나눈 문단이 각각 `<p>`가 된다. 첫 줄의 `**굵은 글씨**`가 박스 제목이 된다.

**면책 문구는 글 끝이 아니라 여기에 쓴다.** 끝에 두면 이미 다 읽은 뒤라 읽을 이유가 없다.
글의 고정 뼈대는 글쓰기톤.md §9.5 참고.

## 인라인 출처 (§49.1)

수치·표·그림 바로 아래에 `[출처]`로 시작하는 줄을 넣으면
작은 회색 글씨로 변환된다.

```markdown
| **8월 27일** | **3.00%** |

[출처] 한국은행 기준금리 · 2026년 8월 27일 적용
```

- **링크도 이 줄에 함께 넣는다.** `· [원문 보기](URL)` 형태
- 링크 문구는 「원문 보기」「공시 보기」「기사 보기」처럼 짧게. URL 자체는 노출하지 않는다
- 한 문단에 출처가 여럿이면 슬래시로 구분

**맨 아래에 [자료 원문 링크] 목록을 따로 만들지 않는다.**
인라인에서 이미 다 보여줬는데 또 나열하면 보고서 부록처럼 보인다.
대신 「자료 확인」 세 줄로 끝낸다 (CLAUDE.md §49.2).

통계표 코드 같은 검증 기록은 독자용이 아니다. numbers.md에 남긴다.

## 꼬리말 분리 — [FOOTER]

본문에 `[FOOTER]` 한 줄을 넣으면, 그 아래는 작은 회색 글씨 블록으로 처리된다.

```markdown
...라는 질문에 스스로 답할 수 있게 됩니다.

[FOOTER]

**참고한 자료**

한국은행 · 전국은행연합회 · 국가데이터처
2026년 9월 6일 기준
```

참고한 자료와 기준일을 여기 넣는다. 면책 문구는 [안내] 박스로 앞에 둔다.
**본문의 마지막 문장이 진짜 마지막 문장으로 남게 하기 위한 장치다** (CLAUDE.md §49.3).

없으면 글 끝이 다시 자료집처럼 보인다.
